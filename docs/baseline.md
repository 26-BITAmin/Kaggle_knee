# Baseline 설계안

디스커션 133개와 공개 커널 40개를 읽고 정리한 것
출처는 `refs/` (gitignore 대상)

## 0. 공개 생태계의 구조

공개된 것들을 다 받아서 계보를 추적한 결과

- 리더보드 상위 공개 노트북이 **전부 `pilkwang/rsna-knee-baseline-v1` 하나에서 갈라졌다**
  0.94대 노트북들의 메타데이터에 `"source": "pilkwang/rsna-knee-baseline-v1"`,
  `"official_source_score": 0.891` 이 그대로 박혀 있다
- 그 위에 쌓인 것은 대부분 **앙상블 가중치 튜닝**이다
  포크 약 200팀이 정확히 0.941에 몰려 있다
- 따라서 "상위권 코드를 전부 합친다"는 성립하지 않는다
  합칠 것이 없고 포크 블록에 합류하는 것뿐이다

우리가 할 일은 이 루트 노트북의 **설계 논리를 이해하고 우리 파이프라인을 짜는 것**이다

## 1. 지표가 결정하는 것

점수는 12개 레이블 AUC의 단순 평균이다

- **순서만 의미 있다** - AUC는 단조 변환에 불변이므로 캘리브레이션과 임계값은 가치가 없다
  앙상블은 확률 평균이 아니라 **rank 평균**이어야 한다
  확률 평균은 가장 자신만만한 모델이 지배하게 두는 것이다
- **모든 레이블의 비중이 같다** - 한 레이블을 chance(0.5)로 버리면
  나머지 11개가 아무리 좋아도 `(M-0.5)/12` 를 잃는다 (M=0.85면 0.029)
  **희귀 소견이 흔한 소견보다 더 중요하다**
- **유병률 드리프트는 견디지만 임계값은 못 견딘다** - 대회가 train/public/private의
  양성률 일치를 보장하지 않는다고 명시한다

## 2. 타깃을 만드는 것이 1단계

`train.csv`에 `Report`가 있고 `test.csv`에는 **없다**

이 스키마 차이가 설계를 결정한다

- 텍스트 분기를 둔 fusion 모델은 불가능하다 - 추론 시 읽을 것이 없다
- 판독문은 **타깃 생성** 또는 **샘플 가중치** 로만 쓸 수 있다

측정된 사실 (디스커션 733932, gold 58건 기준 macro AUC)

| 레이블 소스 | AUC |
|---|---|
| 정규식 / 사전 추출 | 0.8136 |
| LLM 판독문 독해 | 0.8780 |
| + Synovitis 미결정 셀을 Effusion으로 보충 | 0.8873 |
| + 12개 전부에 학습 기반 보충 (일반화) | 0.8805 (악화) |

교훈: **타깃 보충은 근거 있는 한 컬럼만 하고 일반화하지 않는다**

### "판독문에 언급 없음"을 다루는 법

전체 레이블 셀의 25.4%가 미언급이다 소견별 편차가 극단적이다

| 소견 | gold AUC | 미언급 |
|---|---|---|
| Synovitis | 0.678 | 83.7% |
| Baker's | 0.946 | 48.2% |
| Fracture | 0.793 | 42.9% |
| ACL | 0.993 | 8.3% |
| Medial Meniscus | 0.954 | 5.5% |

미언급을 음성으로 뭉개면 안 된다
0.5(미결정)로 두고 **손실에서 마스킹하거나 신뢰도를 샘플 가중치로 쓴다**
판독문이 synovitis를 언급하지 않은 스터디는 그 head를 훨씬 약하게 당겨야 한다

### 다국어 처리

우리 EDA 결과 영어는 40%뿐이다 (네덜란드어 13%, 터키어 12%, 그리스 7%, 키릴 5%)

루트 노트북의 정규식 방식이 채택한 설계

- **언어를 식별하지 않는다** - 9개 언어 큐를 전부 합쳐서 각 절에 대고 본다
  언어 라우팅은 증거를 읽기 전에 추측을 확정하는 것이고 `'la '` 같은 값싼 판별은
  스페인어와 프랑스어를 뭉갠다
- **정규화 → 절 분할 → 스코프** 순서
  대소문자·분음부호를 NFKD로 접는다 (그리스어 판독문이 μ를 U+00B5로 쓰는 문제도 같이 해결)
  `Fractures :` / `Aucune.` 처럼 제목과 값이 두 줄로 나뉜 경우를 붙여야 한다
  안 그러면 부정을 양성으로 읽는다
- **긍정 / 부정 / 유보 3분류** - 부정은 예외가 아니라 다수다
  판독문은 확인했고 정상이었던 것을 나열한다
  명시적 정상 서술도 부정으로 센다
- **구문 뒤에 어간** - 터키어는 소유격 접미사를, 그리스어·크로아티아어는 곡용을 붙인다
  완전 구문 사전이 실패하면 어간 매칭 + 문자 윈도우 내 측면 한정어로 받는다

우리 선택: **LLM 레이블을 우선 쓰고 정규식은 폴백으로 둔다**
공개 LLM 레이블 데이터셋이 4종 있다 (`docs/competition.md` 참고)

## 3. 시퀀스 선택

`train_series.csv`의 `Fluid_Sensitive`와 `Fat_Suppression`이
**24,371개 전부 동일하다** (우리가 직접 검증, `docs/eda.md` 5절)

이름은 물리적으로 독립인 두 속성인데 주어진 컬럼은 한 축만 담고 있다
그래서 루트 노트북은 **DICOM 헤더에서 둘을 복원한다**

- 유체 감응 = 대조 가중 (TR/TE로 결정)
  T1: TR ≲ 800ms / T2: TR ≳ 800ms, TE ≳ 60ms / PD: TR ≳ 800ms, TE ≲ 60ms
  gradient echo는 TR이 짧아 규칙이 깨지므로 `ScanningSequence`로 먼저 거른다
- 지방 억제 = 가중 위에 얹는 준비 과정, 골수 부종을 드러낸다
- `SeriesDescription`, `SequenceName`, `ScanOptions`에 적혀 있으면 그걸 쓰고
  없으면 TR/TE로 판단한다

**결측 분기 로직이 필요 없다** 슬롯 고정 설계가 안전하다

## 4. 슬라이스 순서 - 조용히 틀리는 지점

**파일명 정렬은 틀렸다.** 파일명은 SOP Instance UID이고 고유하게 배정될 뿐 순서가 아니다
실제 물리 위치와의 순위상관이 **ρ ≈ 0.01** 이다

에러가 안 나면서 세 가지가 동시에 망가진다

- 인접 3슬라이스를 3채널로 쌓으면 무관한 단면 3장이 된다
- 스택의 중앙부를 고르면 무작위 부분집합이 된다
- 좌우 정규화를 위해 순서를 뒤집어도 아무 일도 안 일어난다

올바른 순서는 기하로 정확히 복원된다

```
n̂ = r̂x × r̂y          (ImageOrientationPatient)
k  = p · n̂            (ImagePositionPatient)
```

`k`는 스택을 따라 단조 증가하고 환자 좌표계라서 부호가 있다
좌우 정규화가 뒤집는 것이 이 부호다
`InstanceNumber`는 태그가 없을 때의 폴백이지만 interleaved/multi-echo에서는 공간 순서와 다르다

## 5. 물리적 크기 정규화

DICOM 슬라이스가 N×N 픽셀, 간격 s mm/pixel이면 실제로는 Ns 밀리미터를 덮는다
이 값이 코퍼스 전체에서 제각각이라 고정 픽셀 리사이즈는 물리적 배율이 몇 배씩 다른 이미지를 넘긴다

**2픽셀보다 좁은 구조는 리사이즈에서 소멸한다** (Nyquist)

반월상 파열은 1~3mm다 d=1mm를 살리려면 픽셀 피치가 0.5mm 이하여야 한다
못 맞추면 첫 convolution 전에 신호가 파괴되므로 downstream의 어떤 용량으로도 복구 못 한다

```
n = round(L/s) 픽셀,  s_eff = L/P mm/pixel,  token = 14 · s_eff mm
```

- L = 130mm - 거의 모든 시리즈의 FOV보다 작으면서 관절을 담는다
  **L/s가 이미지 폭을 넘으면 크롭이 조용히 무시된다** (에러 없음)
- P = 224 → 0.580 mm/pixel (1mm 구조 기준 한계 초과)
- P = 336 → 0.387 mm/pixel, 14픽셀 패치 토큰이 5.4mm

**강도 정규화**: MR은 절대 스케일이 없다
시리즈별 1/99 백분위수로 정규화하되 슬라이스별이 아니라 **샘플링된 스택 전체 기준**으로
(슬라이스 간 상대 대조를 유지) 극값이 아니라 백분위수로 (혈관 하나가 전체를 압축하지 않게)

## 6. 모델 - 여기는 병목이 아니다

측정된 사실 (디스커션 735154)

DINOv2-Small → Base (22M → 87M, step당 연산 3.9배)
**CV +0.0011, 측정된 노이즈 바닥 0.0020** → 통계적으로 null
12개 중 5개만 Base 쪽으로 움직였고 macro 이득 전부가 가장 약한 레이블 하나에서 나왔다

교훈

- **용량은 병목이 아니다** 전처리와 레이블이 병목이다
- **체크포인트는 자기 전처리 계약을 갖고 다닌다**
  인코더 가중치만 바꾸고 정규화 상수를 안 바꾸면 조용한 핸디캡이 된다
  그럴듯하지만 틀린 결과가 나온다
- **노이즈 바닥을 먼저 측정하라** 그 아래 변화는 해석하면 안 된다

구조는 슬롯별 head + 스터디 단위 집계 인코더는 freeze가 아니라 fine-tune

## 7. 픽셀 캐시 - 실행 비용을 없애는 지점

디코드가 한 fold의 72%(55분)를 먹는다 그런데 모델이 실제로 보는 것은

```
4,407 studies × 6 slots × 9 slices × 224 × 224 uint8 = 11.12 GiB
```

500GB DICOM 중 모델 입력은 11GiB뿐이다
한 번 디코드해서 샤딩된 `.npy`로 저장하고 memory-map으로 읽으면 디코드 비용이 영구히 사라진다

부수 효과가 더 크다 **11GiB는 노트북에 들어간다**
Kaggle GPU 쿼터가 소진돼도 로컬에서 실험을 돌릴 수 있다

| | Kaggle T4 (fp16) | M4 Pro (fp32) |
|---|---|---|
| step당 | 0.227s | 0.436s |
| 캐시 빌드 | 매 실행 55분 | 0 |
| 1 fold | 76분 | 67분 |
| GPU 쿼터 | 21분 | 0 |

> 주의: 같은 설정이 로컬 0.7931 vs Kaggle 0.7957로 갈린 사례가 있다
> fp32/fp16 수치 차이인지 실제 손실인지 분리 못 했다
> **비교는 항상 같은 기계 안에서 한다**

## 8. 추론 속도 (Efficiency Prize)

CoAtNet 기준 40분 → 10분 이하 (디스커션 743374)

- GPU당 모델 1벌 + study 샤딩 (DataParallel은 forward마다 파라미터를 재방송한다)
- DICOM을 스레드로 동시 1회 읽기 - 단일 59 MB/s vs 16스레드 372 MB/s
- pydicom 대신 헤더 직접 파싱 0.307 → 0.058 ms/file
- PixelData 오프셋에서 `np.frombuffer` 직접 읽기 1.22 → 0.33 ms/slice
- 1/99 백분위수를 strided 서브샘플로 (`np.percentile`의 정렬이 디코드의 60%)
- autocast 없이 fp16 가중치 + half 입력 T4에서 2.08배
- uint8로 GPU 전송 후 device에서 정규화, pinned memory, persistent workers

## 9. 검증

- **CV는 스터디 단위 분할**이면 충분하다 (스터디 = 1인 1회 검사)
- **gold 58건은 학습에 넣지 않는다** 레이블 추출기 품질을 재는 유일한 자다
  다만 이미 개발에 쓰였다면 독립 테스트셋이 아니라 development panel로 취급한다
- 레이블이 판독문 유래이므로 **CV는 "판독문을 얼마나 잘 맞추나"를 재는 것**이지
  "무릎을 얼마나 잘 보나"가 아니다 이 둘의 괴리가 이 대회의 본질적 불확실성이다
- 앙상블은 rank 평균 (§1)

## 10. 우리 실행 순서

1. **레이블 테이블 확보** - 공개 LLM 레이블 데이터셋을 붙이고 gold 58건으로 검증
   여기서 0.87대가 안 나오면 다음 단계가 의미 없다
2. **Synovitis 컬럼만 Effusion으로 보충** (근거 있는 한 컬럼, 일반화 금지)
3. **픽셀 캐시 빌드** - Kaggle에서 한 번 돌려 Kaggle Dataset으로 저장
   6슬롯 × 9슬라이스 × 224, 물리 크롭 130mm, 기하 기반 슬라이스 정렬
4. **노이즈 바닥 측정** - 같은 설정 시드만 바꿔 3회, 표준편차를 기록
   이보다 작은 변화는 이후 전부 무시한다
5. **단일 모델 baseline** - DINOv2-S/14, 슬롯 head, BCE + 신뢰도 가중
   목표는 단일 모델 0.88~0.90
6. 그 다음에야 해상도(336), 특화 모델, 앙상블을 본다

**하지 말 것**: 인코더 키우기, 확률 평균 앙상블, 임계값 튜닝, 미언급을 음성으로 처리
