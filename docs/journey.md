## 확정된 설정

학습 (루트 노트북 `pilkwang` 0.891 과 대조해 맞춘 값)

    인코더 lr 8e-6, head lr 1e-3, unfreeze 마지막 6블록
    weight decay 0.02, OneCycleLR pct_start 0.15, 30 epoch
    batch 8 x accum 2 (336 은 4 x 4)
    침묵 셀 가중 0.05, 손실은 (BCE*w).mean()
    9슬라이스 중 한 그룹만 학습 (검증/추론은 전부 평균)
    SlotHead, slot_prior 고정 buffer
    증강 회전 ±8도 / 스케일 ±8% / 이동 ±5% / 밝기 ±10%, 좌우 뒤집기 없음

데이터

    plan C (평면 통합) - T1_1 = COR_T1 or SAG_T1 or T1_EXTRA
    타깃 stevenleehans v4_blend, 0.25 가 "판독문 미언급" 표시
    fold 는 1개만 쓴다. 5-fold 는 마감 직전 최종 제출용

## 4. 픽셀 캐시

DICOM 500GB 중 모델이 보는 것은 일부뿐이다. 한 번 디코드해 저장하면
학습마다 드는 55분이 사라진다

| 캐시 | 구성 | 용량 | mm/px |
|---|---|---|---|
| `knee-cache-build` | 224px 8칸 9슬 | 14.8 GiB | 0.5804 |
| `knee-cache-336` | 336px 6칸 6슬 | 16.7 GiB | 0.3869 |

조용히 틀리는 지점 세 가지를 코드로 막았다 (`src/dicom_io.py`)

- **파일명 정렬은 물리 순서와 무관하다** (순위상관 0.01)
  `ImagePositionPatient · n̂` 로 복원한다
  실측: 기하 순서 27.4 vs 파일명 순서 58.5 (인접 슬라이스 차이)
- **물리 크롭이 원본보다 크면 조용히 무시된다.** `applied=False` 로 알린다
- 시퀀스 판별을 CSV 가 아니라 DICOM 헤더에서 한다 (UNK 7.5% -> 0.0%)

마운트 검증에서 **인덱스와 배열 정렬 불일치 0건**을 확인했다
어긋나면 이미지와 레이블이 뒤바뀐 채로 학습된다

## 5. 학습 - 루트 노트북과의 대조가 전환점

처음 세 번은 **epoch 0 이 최고**였다. 학습이 모델을 망가뜨리고 있었다

| 실행 | 설정 | best |
|---|---|---|
| 1 | 8ep, lr 1e-4, 전체 unfreeze | 0.6622 |
| 2 | 24ep, 동일 | 0.6933 (ep0) |
| 3 | 12ep, lr 8e-6, 증강, prior | 0.7037 (ep0) |
| 4 | **head 단순화 + 손실 4종 정렬** | **0.8260** |
| 5 | 30 epoch | **0.8420** |

루트 노트북 구현을 읽고 5개 차이를 맞춘 것이 4번이다

1. **head 를 SlotHead 로 교체** (0.7M -> 0.107M)
   `nn.MultiheadAttention` 으로 슬롯 6개를 보고 있었다
   > With a study-level label there is no signal telling the model which part
   > of a study matters, so extra attention parameters below the slot level
   > would have nothing to learn from and would spend their capacity fitting noise
2. **침묵 셀 가중 0.3 -> 0.05** (전체 셀의 19%)
3. **손실을 `(BCE*w).mean()` 으로** (가중평균이 아니다)
4. **9슬라이스 중 한 그룹만 학습에 쓴다** (인코더 입력 18장 -> 6장, 3배 빠름)
5. **OneCycleLR** (cosine 은 0 까지만 내려간다)

## 6. 해상도 실험

224 는 0.5804 mm/px 로 1mm 구조의 Nyquist 한계(0.5)를 넘는다

전체 성능은 동률이었다 (0.8420 vs 0.8426) 그러나 레이블별로 갈렸다

| 336 이 나음 | | 224 가 나음 | |
|---|---|---|---|
| ACL | +0.027 | MCL | -0.033 |
| Contusion | +0.024 | Baker's | -0.017 |
| Lateral Meniscus | +0.011 | Effusion | -0.011 |

MCL 이 떨어진 것은 슬라이스가 9->6 으로 줄어든 영향으로 보인다
(출력 한도 20GB 때문에 336 에서 슬라이스를 줄였다)

**서로 다른 것을 보므로 앙상블에 유리하다**

## 8. 공개 가중치 앙상블

`kernels/submit_ens/`, `scripts/make_ens_nb.py`

우리 모델끼리는 상관이 0.83~0.93 으로 높아 앙상블 이득이 작다
구조가 다른 멤버(CoAtNet, RadImageNet, Raptor)를 공개 노트북에서 빌린다

베이스는 `pjmathematician/rsna-knee-d4-lite` (공개 LB 0.943)

    DINOv2 20개 + A5 5 fold + RadImageNet + Raptor 4뷰 + CoAtNet 4종

구성

- **d4-lite 셀 0~29 는 한 글자도 고치지 않는다**
  체크포인트 해시, cv2/timm 버전, T4 2장을 스스로 검사해 조금만 바뀌어도 멈춘다
  docker 이미지도 원본 sha256 으로 고정했다 (`docker_image_pinning_type: original`)
- 원본 셀 30~32 는 버렸다. 작성자의 비공개 데이터셋(eff6/ens14)을 읽는다
- 그 자리에 우리 레그를 넣었다
  공개 결과 보관 -> 우리 224+336 추론 -> rank 블렌드
- 우리 레그는 **서브프로세스**로 GPU 0 한 장에서 돈다
  d4-lite 가 전역에 이름을 수백 개 깔고, 우리 모듈 이름(paths, config, model)이 흔하다
- 우리 레그가 실패하거나 9시간 한도에 걸리면 **공개 결과를 그대로 제출한다**
- 블렌드 가중치는 우리 몫 0.15 하나
  공개 모델들의 OOF 가 없어 오프라인으로 잴 수 없다. LB 로 조정한다

공개 3건 실행 결과

    d4-lite 4.9분, 자체 검사 통과
    우리 레그 rc=0, 총 5.3분, 최종 "우리 w=0.15 블렌드"

3건에서는 순위가 세 칸뿐이라 15% 로 순서가 안 바뀌어 제출값이 공개 결과와 같다
실채점(약 1,300건)에서 달라진다

`check_notebook.py` 가 d4-lite 셀을 막아서 검사기를 고쳤다

- 함수 본문 안의 이름은 호출 시점에 찾으므로 노트북 어딘가에서 정의되면 통과
  최상위 코드는 전처럼 앞 셀에서 정의돼야 한다
- 도달하지 않는 분기의 이름(`augment`)은 노트북 메타데이터 `allow_undefined` 에 사유와 함께 명시한다

### 결과 - LB 0.943, d4-lite 단독과 같다

채점이 제출부터 점수까지 약 8시간 50분 걸렸다 (밤 대기열 포함)
같은 점수가 나온 이유는 둘 중 하나다

1. 우리 레그가 섞였지만 차이가 너무 작다
   0.877 모델을 0.943 에 15% 섞으면 득실이 거의 상쇄되고 LB 는 소수 셋째 자리까지만 보인다
2. **우리 레그가 timeout 에 걸려 공개 결과만 제출됐다** (더 유력)
   9시간에 붙은 채점 시간이 이 경우와 맞는다
   d4-lite 의 A5 단계가 `AMP_PREF = 'bf16'` 으로 T4 에서 bf16 을 강제한다
   T4 에는 bf16 연산기가 없어 약 50배 느려진다 (디스커션 744230)
   우리 코드는 autocast 기본값 fp16 이라 해당 없다

실채점 로그는 볼 수 없어 확정하지 못했다
학습 데이터 50건으로 우리 레그 시간을 재서 1,300건으로 환산하면 가를 수 있다

**공개 앙상블에 기대지 않기로 했다**

- 0.943 에 622팀이 동점이다. private 에서 같이 움직이니 순위 차별화가 안 된다
- 공개 가중치는 우리 검증 fold 로 학습됐을 수 있어 OOF 로 검증할 수 없다
- 공개 가중치를 쓴 제출의 상금 자격이 미정이다 (744056)

최종 제출 2개 중 하나의 보험으로만 남기고 우리 모델을 끌어올린다

## 9. 우리 모델 끌어올리기 - 실험 A~C

### 진단

판독문 유래 레이블 val 과 LB 의 관계는 다른 팀과 같다 (+0.02~0.03)
그런데 **val 자체가 0.03~0.06 낮다** (우리 0.842, 다른 팀 0.87~0.90)
같은 종류의 레이블로 학습하므로 레이블보다 입력과 모델 쪽 문제로 본다

의심 지점 - `src/cache.py` 가 시리즈마다 **정중앙 연속 9장만** 고른다
슬라이스 3~4mm 면 무릎 가운데 약 30mm 뿐이고 학습 때는 그중 3장만 본다
시상면에서 내외측 구획을 놓칠 수 있고 가장 약한 MCL 0.748, Lateral Meniscus 0.760 이 정확히 그쪽이다

### 실험 계획 (모두 fold 0, 기준 val 0.842)

| 순서 | 실험 | 근거 | 성격 |
|---|---|---|---|
| A | 백본 12블록 전체 학습 + 층별 lr 감쇠 | 푸는 층 수와 점수의 상관 (735304) | DINOv2 개선 |
| B | 슬라이스 범위 넓히기 + 크롭 130 -> 150mm | 100 -> 140mm 로 크게 개선 (735304) | 입력 개선 |
| C | CNN 백본 (ResNet50 또는 CoAtNet) | 상위 단일 모델 다수가 CNN | **앙상블 멤버 추가** |
| D | 5-fold -> OOF 예측을 레이블에 섞어 재학습 | 0.949~0.950 사례 3건 | 최종 학습 방식 |

- A 가 GPU 에서 도는 동안 B 의 캐시를 CPU 커널로 빌드한다
- D 는 OOF 가 있어야 하고 비용이 5배라 A~C 로 설정을 굳힌 뒤 한 번에 돌린다
- 레이블 블렌드(v4_blend + pilkwang v2, gold 0.8940)는 D 에 같이 넣는다

최종 그림

    DINOv2 (A, B 로 개선) x 5 fold  ┐
                                    ├ rank 평균 -> 제출
    CNN    (C)            x 5 fold  ┘

### 결과 (fold 0, 기준 224 DINOv2 val 0.8420)

| 실험 | val | 결론 |
|---|---|---|
| A 백본 전체 학습 | 0.8424 | **효과 없음.** 후반 평균은 오히려 0.0016 낮고 시간 1.7배 |
| B 분산 배치 (30ep) | 0.8392 | 단독은 같다. **반월상연골이 오른다** (LM +0.042, MM +0.018), MCL -0.034 |
| B15 (15ep) | 0.8395 | B 와 같고 과적합 없이 수렴, 시간 절반 |
| ResNet50 | 0.8154 | 12개 중 11개가 낮다. 앙상블 w=0.3 에서도 +0.0003 |
| **CoAtNet-2** | **0.8489** | 최고 단일. 같은 중앙 캐시인데 LM +0.065, gold 0.910 |

해석

- A 와 ResNet 이 안 됐다. **백본을 얼마나 열거나 무엇으로 바꾸는 것은 병목이 아니다**
- B 는 가설대로 반월상연골을 올렸다. 시상면 중앙 30mm 밖을 보게 한 효과다
  MCL 이 내린 것은 관상면에서 분산하면 앞뒤로 퍼져 중앙 비중이 줄기 때문으로 본다
- CoAtNet 의 LM +0.065 는 입력이 같으므로 모델 표현력 쪽 이득이다
- B 는 매 스텝 묶음 3개를 다 봐서 무작위 한 묶음 학습의 증강 효과가 없다. 그래서 ep10 에서 과적합했다
  B30 의 0.8392 는 내려가는 곡선의 봉우리를 고른 값이라 조금 부풀려졌을 수 있다

  그래서 평면별 배치 캐시(시상면만 분산)는 보류했다

## 작업 규칙

- `src/` 를 고치면 `bash scripts/push_src.sh` 를 먼저 돌린다
  `push_kernel.sh` 가 동기화를 검사해 막는다
- 노트북을 스크립트로 수정했으면 `scripts/check_notebook.py` 로 확인한다
- 커널 출력 한도 20GB. 336px 로 9슬라이스를 담으면 25GB 로 초과한다
- Kaggle 큐는 한국 시간 밤에 길고 오전에 짧다 (실측: 22시 43분 대기, 10시 즉시)
- GPU 할당량 주당 30시간, 매주 금요일 갱신
- GPU 배치 세션은 **동시에 2개까지**. 세 번째는 `Maximum batch GPU session count of 2` 로 거부된다
- 커널 세션 한도 12시간
- **새 커널은 docker 이미지를 고정한다.** 기본 이미지가 Python 3.13 으로 바뀌어 `knee-dicom-wheels`(3.12) 설치가 실패한다
  CPU 캐시 빌드 `kaggle-images/python@sha256:dafd4ce5…`, GPU 학습/제출 `kaggle-private-byod/python@sha256:37c64f7d…`
- **로컬(맥)에서 학습을 돌리지 않는다.** GPU 가 없고 디스크가 찬다. 스모크도 Kaggle `DEBUG=True` 로
